# Security Notes

## Simulation only — never real infrastructure

Every state-changing action in CrisisDesk (`execute_remediation`,
`correlate_evidence`, `create_root_cause_hypothesis`,
`create_remediation_plan`) mutates a local, in-browser simulation store
(`lib/data/store.ts`) — nothing shells out, calls a cloud provider API, or
touches any real system. There is no `kubectl`, no AWS SDK, no database
credential anywhere in this codebase.

## API key handling

`GEMINI_API_KEY` is read only in server-only modules (`lib/ai/gemini.ts`,
`src/app/api/agent/route.ts`) and is never sent to the client, logged, or
included in any response body. The Settings page reports only whether it is
configured (`!!process.env.GEMINI_API_KEY`), never its value. `.env*` is
git-ignored by the default Next.js `.gitignore`.

## Tool input validation

Every WebMCP tool executor (`lib/webmcp/toolExecutors.ts`) validates its input
shape before touching the data layer and returns a structured
`{ success: false, error: { code, message } }` result — via `isError: true` on
the WebMCP result — for missing/malformed fields, unknown incidents, and
unknown services, rather than throwing or trusting caller input. `wrapLogged`
also catches any exception a tool implementation might throw and converts it
to the same structured-error shape, so one failing tool call can't take down
the agent loop or the UI.

## Prompt injection

Tool outputs (logs, metrics) are synthetic data generated by CrisisDesk
itself, not third-party or user-supplied content, so indirect prompt
injection via tool results is not a live concern in this build. If real log
data were ever wired in, the WebMCP spec's `annotations.untrustedContentHint`
(already modeled in `lib/webmcp/types.ts`) is the mechanism to flag it — see
the "Prompt Injection Risks" section of
[developer.chrome.com/docs/ai/webmcp/secure-tools](https://developer.chrome.com/docs/ai/webmcp/secure-tools),
cited in `docs/webmcp-research.md`.

## Human-in-the-loop is enforced in code, not just UI copy

`execute_remediation`'s `execute()` function literally `await`s a Promise
(`lib/webmcp/approval.ts`) that only resolves when a human clicks Approve or
Cancel in `components/agent/approval-dialog.tsx`. There is no code path,
including a malformed or adversarial tool call from the LLM, that reaches the
simulation mutation without that `await` resolving to `true` first.

## Cross-origin

CrisisDesk registers tools with no `exposedTo` option, so — under real
WebMCP — they default to same-origin visibility only. There is no
cross-origin tool sharing in this build.
